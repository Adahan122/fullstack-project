## АРХИТЕКТУРА (2 минуты)

Проект построен на двух главных компонентах: **фронтенд на React** и **бэкенд на Node.js**.

### На фронтенде

Я использовал **React с Vite**. React — это стандарт индустрии, он позволяет разбить интерфейс на компоненты, которые легко переиспользовать. **Vite** — это инструмент сборки, который работает нереально быстро. Когда я меняю код, горячая перезагрузка происходит за миллисекунды. Это **огромное** удобство при разработке.

Для управления состоянием я использую **Context API** из коробки React. Это простое, понятное решение. Когда проект растет и становится огромным, можно переходить на Redux или MobX, но для текущего размера — это идеально.

_(пауза)_

### На бэкенде

**Node.js с Express**. Это быстрый и минималистичный фреймворк. Я сделал **RESTful API**, который обрабатывает все запросы — поиск товаров, аутентификацию, работу с заказами. Non-blocking I/O значит, что сервер может одновременно обработать множество запросов без замораживания.

### Развертывание

**Docker + Docker Compose** для локальной разработки, и **Render** для production. Это значит что приложение одинаково работает на моем ноутбуке, ноутбуке коллеги и на облачном сервере. Один образ — везде одно поведение.

## ФУНКЦИОНАЛЬНОСТЬ (1.5 минуты)

Приложение имеет полный набор фич для нормального интернет-магазина:

- Каталог товаров с фильтрацией
- Система поиска с debouncing'ом — это значит, что запросы отправляются не при каждой букве, а после того как пользователь перестанет писать. Это сберегает трафик
- Рекомендации товаров через карусель
- Корзина, оформление заказа
- Личный кабинет с историей заказов
- Избранное
- Admin панель для управления товарами и пользователями

_(пауза)_

Все это адаптировано под мобильный и десктоп. Приложение выглядит хорошо везде.

## АРХИТЕКТУРНЫЕ РЕШЕНИЯ (1 минута)

**Разделение ответственности** — бэкенд отвечает за логику и безопасность, фронтенд за интерфейс. Бэкенд никогда не доверяет фронтенду — вся валидация переделывается.

**JWT для аутентификации** — безопасный способ, токены не хранят пароли.

**Хеширование паролей** через bcrypt — даже если кто-то сломает БД, пароли неуязвимы.

**CORS и HTTPS** для безопасности. На production Render автоматически выдает SSL сертификат.
