# ПРОМТ ДЛЯ СОЗДАНИЯ ПРЕЗЕНТАЦИИ ПРОЕКТА SportMix

Ты создаешь 5-7 минутный промт (текст для устной презентации) дипломного проекта на защите ВКР перед комиссией.

## ИНФОРМАЦИЯ О ПРОЕКТЕ

**Название**: SportMix  
**Тип**: Full-stack веб-приложение для электронной коммерции  
**Предназначение**: Продажа спортивных товаров онлайн

### Стек технологий

**Frontend**:

- React (фреймворк)
- Vite (инструмент сборки)
- Context API (управление состоянием)
- CSS (стилизация)

**Backend**:

- Node.js
- Express.js (фреймворк)
- REST API
- JWT (аутентификация)

**DevOps & Deployment**:

- Docker + Docker Compose
- Nginx (reverse proxy)
- Render (cloud hosting)

### Функциональность приложения

**Для пользователей**:

- Каталог товаров с фильтрацией и поиском
- Debounced поиск (оптимизированный)
- Система рекомендаций (Swiper компонент)
- Корзина покупок
- Оформление заказов
- Личный кабинет с историей заказов
- Список избранных товаров
- Аутентификация и регистрация

**Для администраторов**:

- Админ панель управления товарами
- Управление пользователями
- Просмотр заказов

### Архитектурные особенности

- Разделение ответственности frontend/backend
- JWT токены для безопасности
- Хеширование паролей (bcrypt)
- CORS конфигурация
- HTTPS на production
- Responsive дизайн (мобильный + десктоп)

## ТРЕБОВАНИЯ К ПРОМТУ

### Формат

- **Жанр**: Устная презентация (как будто говоришь вслух)
- **Стиль**: Профессиональный, но человеческий (не формальная википедия)
- **Длина**: 5-7 минут чтения вслух в нормальном темпе
- **Язык**: Русский

### Структура презентации

1. **ВСТУПЛЕНИЕ** (30 сек - 1 мин)
   - Приветствие
   - Краткое что это за проект
   - Почему выбрана эта идея

2. **АРХИТЕКТУРА** (2-2.5 мин)
   - Что на фронтенде (React, Vite, Context API)
   - Почему эти технологии выбраны
   - Что на бэкенде (Node.js, Express, API)
   - Как развертывается (Docker, Render)

3. **ФУНКЦИОНАЛЬНОСТЬ** (1.5-2 мин)
   - Ключевые фичи для пользователя
   - Технические решения (debouncing, адаптивность)
   - Админ функции

4. **ПОЧЕМУ ТАК СПРОЕКТИРОВАНО** (1 мин)
   - Разделение ответственности
   - Security подход
   - Масштабируемость
   - Production-ready

5. **ЗАКЛЮЧЕНИЕ** (30 сек)
   - Что показал этот проект (навыки, знания)
   - Спасибо за внимание / готов к вопросам

### Тон и стиль

✅ **ДЕЛАЙ**:

- Говори как опытный разработчик, который понимает что делает
- Используй примеры из реальной работы ("когда пользователь печатает, мы ждем...")
- Объясняй ПОЧЕМУ выбраны технологии, а не просто перечисляй их
- Демонстрируй понимание (не просто "используем Docker", а "Docker гарантирует одинаковое поведение везде")
- Будь уверен в себе
- Включай паузы между ключевыми моментами

❌ **НЕ ДЕЛАЙ**:

- Не читай как робот/википедия
- Не используй слишком много эмодзи (максимум в заголовках)
- Не перегружай жаргоном без объяснений
- Не говори "я думаю", "может быть", "наверное" — говори уверенно
- Не делай слишком длинные сложные предложения

### Ключевые моменты, которые ОБЯЗАТЕЛЬНО включить

1. **React + Vite** — почему это современный стандарт
2. **Context API** — простое и эффективное решение для управления состоянием
3. **Debouncing** — конкретный пример оптимизации
4. **Docker** — важность одинаковой среды везде
5. **JWT + bcrypt** — security на серьезном уровне
6. **Responsive дизайн** — приложение работает везде
7. **Full-stack** — демонстрация знания полного цикла разработки

### Язык и выражения

Используй естественный разговорный русский язык:

- "Я использовал..." вместо "Был использован..."
- "Это дает нам..." вместо "Это обеспечивает..."
- "Когда пользователь..." вместо "В случае взаимодействия пользователя..."
- Короткие энергичные предложения вместо длинных запутанных
